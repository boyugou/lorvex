# Lorvex 1.0.0 (177)

**Codex Desktop, and any other assistant that declares extra capabilities
when it connects, can now use Lorvex over MCP.** A Codex chat declares
`"codex/auth-change": {}` among its experimental capabilities. The MCP
library inside Lorvex's helper could not read that value, so the helper
answered the chat's first request with error -32603 and the chat saw no
Lorvex tools, even though Codex's own connection check listed them. The
helper now ignores the client capabilities it does not use. The launch
command and the setup without arguments are unchanged.

Also in this build:

- **Consistent animation timing.** The 145 animations in the apps used 28
  different curves, often different ones for the same kind of change on
  different screens. Each now uses one of nine shared timings: a control
  answering its own tap is quick (0.18 s), rows joining or leaving a list
  and panels sliding take 0.25 s, the iPhone calendar's pages and the setup
  steps 0.35 s. Progress bars and rings no longer overshoot their value.
- **The Mac's Dock badge and widgets** now update from one read of the
  data instead of two. A refresh that read before a completion and
  finished after it can no longer put the older badge count back.
- **Spotlight's calendar index on the Mac and the calendar event list in
  Shortcuts** read their events in one database transaction instead of one
  each.

For the project rather than testers:

- **The cause of build 176's stalled hosted check is fixed.** That check
  stopped for 30 minutes because blocking waits held every thread of
  Swift's shared thread pool; the build 176 record has the details. The Mac
  settings panel's helper check now reads the helper's output on a GCD
  queue, and the tests that pause synchronous code run those tasks on their
  own queue. A run on this Mac with a one-thread pool passes (below); the
  hosted result is at the end of the verification section.
- **Responsiveness is measured.** `script/ios_sim_responsiveness.sh` times
  launch, scrolling each main screen, switching tabs, opening a task and
  opening capture in the iPhone simulator. `ROADMAP.md` has the first
  numbers: scrolling is mostly smooth, and the three screen changes hold
  the main thread for up to 353 to 599 ms, almost all of it SwiftUI and
  Core Animation work on the app's view tree rather than the app's own
  code.

## Verification

The full suites passed on the tree before the last two source changes. The
app package ran 5,499 Swift Testing tests and 680 XCTest tests, 2 of them
skipped. Nothing in the core package changed since build 176, so its suite
was not run. Every static gate passed, before and after the last commits.

Two changes came after the full run. The Shortcuts calendar query's
batched read passed its tests, extended with a duplicate and a missing id.
The build number change passed the app metadata tests.

The thread-pool fix was also checked with
`LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`, which gives the pool one thread:
the app test bundle (5,270 tests, before the review corrections added
four) passed in 358 s, where before the fix it stopped after about 250 s.

The MCP fix has unit tests that run a Codex-shaped handshake end to end
and check that a connection ends with its client. The stdio smoke check
sent the same handshake to the built development helper over a temporary
database and called `get_overview`. A real Codex Desktop chat against
this build has not been tried yet.

Four independent reviews read the changes before they were committed.
Each got the diff and a description of its intent, not the author's
conclusions.

- **MCP.** Found nothing significant. It found that no test covered the
  connection ending, and that the pass-through test never reached the
  method check. Both are now tested.
- **Thread pool.** Found no correctness defect. Five more tests paused on
  the shared pool; they now use their own queue as well. It also found
  stale comments, a quarantine test whose two openers were no longer
  structured tasks, and waits that a failing test would never release. All
  are fixed.
- **Animation timing.** Found nothing broken for a person using the app,
  but about 20 call sites contradicted the design system's table. The call
  sites were moved and the table reworded so that they agree. The new
  check that rejects literal curves skipped every file exempted from the
  color rules; it now has its own exemption list.
- **Mac surfaces.** Found no serious defect. A publish that a newer one
  overtook could set an older badge count; it now sets nothing. An
  editable calendar event whose stored row disappeared between two reads
  is now left out of Spotlight until the next refresh; that change was
  kept and recorded. It asked for behavior tests in place of a removed
  source check, an empty-input guard and a deleted-event case for the
  batch read, and three corrected comments; all were added. Its suggestion
  to batch the Shortcuts calendar query is in this build.

The built metadata was read in what shipped. The iOS package and the Mac
App Store package each carry build 177 and hold 89 actions, every one with
a declared lock policy, as in build 176.

The hosted check on the build commit, a second run from a clean checkout
on a machine set to UTC, was started before the build was archived (GitHub
Actions run 45285183300); the upload does not wait for it. Its result is
recorded here when it finishes.
