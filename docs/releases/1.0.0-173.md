# Lorvex 1.0.0 (173)

On iOS 27, iPadOS 27 and macOS 27, **Siri can work with Lorvex tasks the way
it works with reminders**. Ask in your own words and name Lorvex: Siri can add
a task with notes, tags, a list, a day and a time, a flag and a repeat; change
any of those; mark a task done or not done; delete tasks; and create a list.
This uses the version of Siri that arrives with these systems, which Apple
offers in some languages and regions
([Apple's requirements](https://support.apple.com/en-us/127893)).

A reminder and a Lorvex task are not the same shape, so a few things land in a
particular place:

- The day and time given to Siri become the task's planned day and time, the
  day you mean to work on it. They do not set a deadline.
- A flag makes the task P1. A link is added to the notes.
- A task repeats by day, week, month or year. A repeat on a day some months
  lack, such as the 31st, skips them, as every Lorvex repeat does.
- Deleting through Siri cancels the task after asking. It stays in Lorvex,
  where it can be reopened, and a repeating task stops repeating.
- Adding a task works on a locked device. Changing, deleting and creating a
  list need it unlocked.

The [user guide](../../apps/apple/docs/USER_GUIDE.md) has the full list.

Also in this build:

- **Shortcuts and Siri actions carry their lock requirement in the app's
  built metadata.** The code named a policy for every action, but supplied it
  in a way the build's metadata step does not read. Build 172's Mac metadata
  records 79 of its 80 app actions as allowed on a locked device, although 76
  of them name a policy that needs an unlocked device or a passcode or
  biometric check. Every action now declares its policy where the build
  reads it, and two checks fail a build that does not. Whether the system
  decided lock-screen access from the metadata or from the running app is
  not measured, so it is not known whether a locked device could run those
  actions before this build.
- The two widget buttons that complete a task or a habit are recorded as not
  discoverable, for the same reason: build 172's metadata records them as
  discoverable. Whether Shortcuts listed them as actions was not checked.
- On macOS 27, the **Move to List** menus show each list's symbol again.

## Verification

The full suites passed on the commit before the build number changed: 218
core tests and 5,237 app tests. Every static gate passed.

The built metadata was read in what shipped. The iOS package, the Mac App
Store package and the notarized Mac app each hold 89 actions, on the Mac 84 in
the app and 5 in the widget extension, and every one records a declared
policy that matches its source: 67 need an unlocked device, 12 need a
passcode or biometric check, and 10 are allowed on a locked device (adding a
task, opening the app, the widget buttons, and the widget and Focus
configuration). The four Siri actions are recorded as visible to the
assistant only.

Two independent reviews read the change before it was committed.

- The review of the Siri conversion found eleven issues, three of them in
  the repeat rule: an every-other-week rule lost the day its week starts on,
  a rule on a day that does not exist got a first due day the stored rule
  never lands on, and a repeat's end day moved one day later when it fell on
  the day the clocks go forward. Nine are fixed and have behavior tests,
  among them a test that completes an every-other-week task and checks the
  day its next occurrence is due. Two describe how a task works and are now
  stated in the code's documentation: a repeat rule moves the due day while
  the planned day keeps its distance from it, and a change that sets fields,
  a repeat and a completion is three writes.
- The review of the lock-requirement change found the edit itself correct
  and the source check too narrow: it did not read several ways of declaring
  an intent that the code does not use today. The check now reads them, and
  fails on the two forms that would hide an intent from it.

Not exercised by automation:

- What Siri does with the actions: whether it picks Lorvex for a request,
  what it says, and whether a delete asks twice. Tests run the actions
  against the store; nothing drives Siri.
- A locked device. The metadata and the running app now agree on each
  action's policy; what a locked iPhone allows was not tried.

Both are listed for hand evaluation in the [roadmap](../../ROADMAP.md).
